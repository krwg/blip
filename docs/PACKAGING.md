# Packaging — Windows, Linux, macOS 12+

BLIP ships desktop installers via [electron-builder](https://www.electron.build/) (`electron-builder.yml`). Windows remains the primary day-to-day target; **Linux** and **macOS 12+ (Monterey)** are first-class build targets from Morse onward ([#81](https://github.com/krwg/blip/issues/81)).

## Artifacts

| Platform | Targets | Typical output |
|----------|---------|----------------|
| Windows | NSIS Setup, Portable | `BLIP-Setup-<ver>.exe`, `BLIP-<ver>-Portable.exe`, `latest.yml` |
| macOS 12+ | DMG + ZIP | `BLIP-<ver>-mac-*.dmg`, `BLIP-<ver>-mac-*.zip`, `latest-mac.yml` |
| Linux | AppImage, deb | `BLIP-<ver>*.AppImage`, `blip_*.deb`, `latest-linux.yml` |

Outputs land in `dist-electron/`.

## npm scripts

```bash
npm run electron:build              # Windows NSIS (default)
npm run electron:build:portable     # Windows portable
npm run electron:build:win          # Windows NSIS + portable
npm run electron:build:mac          # macOS DMG + zip (run on macOS)
npm run electron:build:linux        # Linux AppImage + deb (run on Linux)
npm run electron:publish:win        # Windows → GitHub Release
npm run electron:publish:mac        # macOS → GitHub Release
npm run electron:publish:linux      # Linux → GitHub Release
```

Release CI (tag push) builds **windows / linux / macos** runners in [`.github/workflows/release.yml`](../.github/workflows/release.yml).

## macOS installer (DMG)

- **Minimum OS:** `12.0` (`LSMinimumSystemVersion` / `mac.minimumSystemVersion`).
- **Category:** `public.app-category.social-networking`.
- **Styled DMG:** `build/dmg-background.png` (+ `@2x`) generated by `npm run build:dmg-background` (also invoked from icon build). Layout: app icon left → Applications right.
- **Hardened Runtime + entitlements:** `build/entitlements.mac.plist` (JIT, camera/mic, local network client/server for mesh).
- **Icon:** electron-builder converts `build/icon.png` → `.icns` on macOS hosts. Prefer building mac packages **on macOS**.

### Gatekeeper, signing, notarization

Unsigned local DMGs open with **right-click → Open** the first time (Gatekeeper). For distribution outside your machine:

1. Apple Developer ID Application certificate (`CSC_LINK` / keychain identity).
2. Notarization (`APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`) — electron-builder `notarize` when credentials are present.
3. Without notarization, users still hit quarantine dialogs on download.

CI mac jobs publish unsigned/ad-hoc builds unless repository secrets for signing are configured.

### Tray (menu bar) on macOS

| Topic | Behavior |
|-------|----------|
| Icon | Lives in the **menu bar**, not the Windows-style notification area. |
| Click | Left-click often only opens the **context menu** (Electron Tray); use **Show** / **Quit** from the menu. Double-click is unreliable — do not rely on it. |
| Close to tray | Closing the window **hides** the app; Dock may still show the icon depending on hide policy. Quit fully from tray menu or **⌘Q**. |
| Dark/light | Template / monochrome tray assets read better; pixel tray PNGs may look muddy on Retina — regenerate higher-DPI trays later if needed. |
| Permission | No special TCC prompt for a menu-bar tray alone. |

### Launch at login (macOS)

- Uses Electron `app.setLoginItemSettings({ openAtLogin })` → **Login Items** (System Settings → General → Login Items).
- User can disable BLIP there even if the in-app toggle stays on — re-open Settings to re-sync expectation.
- **Sandbox / MAS** builds need a login helper + entitlements; current desktop DMG is **not** Mac App Store sandboxed.
- First launch after enabling may still require unlocking the app once for Gatekeeper.

### Auto-update (macOS)

Squirrel.Mac expects **both** `dmg` and `zip` on the release (see electron-builder docs). Feed file: `latest-mac.yml`. Notarized builds update more smoothly; unsigned feeds may fail signature checks depending on updater settings.

## Linux packaging

- **AppImage** — portable single file; FUSE required on some distros (`libfuse2` on Ubuntu 22+).
- **deb** — Debian/Ubuntu family; install then run `blip` from the menu.
- Tray: depends on desktop environment (GNOME may hide legacy tray behind extensions; KDE/XFCE are usually fine).
- Launch at login: Electron login-item APIs map to `.desktop` autostart where supported; behavior varies by DE.
- Auto-update: `latest-linux.yml` for AppImage when published via electron-builder.

## Protocol / file associations

- `blip://` URL scheme and `.blip` seed association are registered by the installer on each OS where electron-builder supports them.
- Packaged non-Windows builds also call `setAsDefaultProtocolClient('blip')` at runtime when possible.

## Maintainer checklist

1. `npm run setup:build-secrets` (Giphy / MESH+ public key sync helpers).
2. Bump [`app-metadata.json`](../app-metadata.json) + [`CHANGELOG.md`](../CHANGELOG.md).
3. Tag `2.0.0` (or current) → Release workflow uploads per-OS artifacts.
4. Confirm `latest.yml` / `latest-mac.yml` / `latest-linux.yml` exist on the GitHub Release for in-app update feeds.
